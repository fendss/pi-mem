## Database isolation result

Only 70/500 paired rollouts generated byte-equivalent first Search arguments. For all 70:

- ordered Search candidate output was exactly identical: 70/70;
- candidate-set Jaccard was 1.0;
- Top-20 overlap was 100%.

After receiving those identical candidate lists, only 16/70 rollouts generated the same second-tool arguments. Thus most trajectory divergence begins in model query/read selection rather than in SQLite-vs-Qdrant retrieval output.

This agrees with the independent 200-query Qdrant parity audit: Recall@400 and Top-20 overlap were both 100%.

## Forced-constraint audit

Historical exact Finish errors:

- 19 attempts after a different selection had already been accepted;
- 17 `finish must be the final tool call in its turn` errors;
- 16 malformed Finish payloads.

Qdrant v3/16 Finish errors:

- 10 `finish must be the final tool call in its turn` errors;
- 6 malformed Finish payloads.

The rejected v6 consistency run added 45 duplicate-citation rejections. The duplicates were usually legitimate separate atomic facts supported by one raw memory. One question retried the same rejected package six times. This confirms that enforcing one citation per memory caused corrective loops without improving provenance.

Pi Agent terminates a tool batch only if **every** tool result in the batch has `terminate=true`. Therefore a valid Finish issued together with Search/Read can be accepted by the ledger but fail to stop the Agent, causing later `different evidence selection` errors and additional turns.

## Low-churn changes

The v8 experiment therefore:

1. accepts multiple atomic citation supports from the same immutable memory;
2. removes duplicate-inventory rejection;
3. replaces Finish-order rejection with batch-aware deterministic termination: if a batch contains a valid Finish and every call succeeds, all results opt into termination;
4. returns the first protocol-valid Retrieval result, including `insufficient`, instead of rerolling it and selecting a later result;
5. retries only provider/protocol failures;
6. restores public bounds to the main-era `64` turns, `80` tool calls, and `2` protocol nudges instead of `1024/4096/8`;
7. retains temperature-zero Retrieval sampling, immutable provenance, and all bottom Search operators.

No Answer prompt, Answer call, retrieval operator, ranking algorithm, SQLite data, or Qdrant index behavior is changed.
